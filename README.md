# 株式会社LIFEFUND PR実績アーカイブ／メディアキット／代表 紹介文集

> メディア関係者向けの公開ページ3つを、**1つのGoogleスプレッドシート**で管理しています。  
> **スプレッドシートの行を追加・編集・削除するだけで、3ページすべてに自動反映されます。**

| ページ | ファイル | 内容 |
|---|---|---|
| メディアキット | `mediakit.html` | 会社概要・代表プロフィール・事業ブランド・取材可能テーマ・ロゴ/写真素材・注意事項・問い合わせ先・実績の抜粋 |
| PR実績アーカイブ | `index.html` | プレスリリース・メディア掲載・講演・受賞歴・ビジョン・PRトピックの全件 |
| 代表 紹介文集 | `shacho_introduction_archive.html` | 白都卓磨の紹介文（用途別）を検索・コピーできる一覧 |

---

## ⚠️ 重要：このサイトに載せてよい情報のルール

このアーカイブは**外部公開**されており、メディア関係者の取材リソースとして使われます。
以下のルールを必ず守ってください。

### ✅ 載せてよいもの（公開済み情報のみ）

- PR TIMES等で**配信済み**のプレスリリース
- すでに**公開・放送・掲載された**メディア露出
- すでに**開催済み**の講演・登壇（または公式に告知済みの予定）
- **正式に発表された**受賞歴
- **公開可能な**PR上の取り組み・事業情報

### ❌ 載せてはいけないもの

- **未公開のリリース**（配信予定日が未到来のもの）
- **下書き・社内検討中**の情報
- **社内メモ・個人情報**
- 取引先・顧客の未公開情報
- **未確定の交渉・契約情報**

### 📌 未来目標・ビジョンの扱い

「BLUEPRINT 2036」「中期経営計画」「将来の展望」などの**未来目標**は、
過去の**実績と混在しないよう**専用の `vision` タブで管理してください。
サイト上も「未来目標であり実績ではない」旨が明示的に表示されます。

## 📝 運用フロー（PR担当の方へ）

1. **情報が公開される**（PR TIMES配信完了 / 記事公開 / イベント終了 など）
2. スプレッドシートの該当タブに行を追加
3. **`meta` タブの `last_updated` を更新**（運用ルール）
4. 数分以内にサイトに自動反映

### よくある更新

| やりたいこと | 操作するタブ |
|---|---|
| 売上高・棟数・従業員数などの数字を更新 | `variables` の value を書き換える（全ページの `{{変数名}}` が一斉に更新） |
| 会社概要の項目を増やす・減らす | `company_profile` に行を追加・削除 |
| メディアキットに載せる代表プロフィールを差し替える | `ceo_profiles` の `featured_on_mediakit` を TRUE にする行を変える（1行だけ） |
| 紹介文集に紹介文を追加 | `ceo_profiles` に行を追加 |
| ロゴ・写真を追加・差し替え | Googleドライブの素材フォルダにアップロード → 共有リンクを `assets` の url に貼る |
| 一時的に非表示にしたい | その行の `hidden` 列に TRUE（削除せずに隠せる） |

## 🚀 初期セットアップ（最初の1回のみ）

### STEP 1. Googleスプレッドシートを準備

以下の**16タブ**を使います（8〜16はメディアキット・紹介文集用）。
8〜16は `メディアキット_新タブ取り込み用.xlsx` を「ファイル → インポート → アップロード → 新しいシートを挿入」で一括追加できます。

| # | タブ名 | 用途 |
|---|---|---|
| 1 | press_releases | プレスリリース（公開済み） |
| 2 | media_coverage | 外部メディア掲載（公開済み） |
| 3 | speaking | 講演・登壇（開催済み or 公式告知済み） |
| 4 | awards | 受賞歴（正式発表済み） |
| 5 | vision | **未来目標・ビジョン**（実績と分離） |
| 6 | topics | PRトピック・事業説明 |
| 7 | meta | **データ最終更新日など** |
| 8 | variables | 売上高・棟数などの**変数**（本文中の `{{変数名}}` に差し込まれる） |
| 9 | company_profile | 会社概要 |
| 10 | contact | 問い合わせ先 |
| 11 | ceo_profiles | 代表プロフィール文（メディアキット＋紹介文集） |
| 12 | ceo_links | 代表のインタビュー記事などの関連リンク |
| 13 | brands | 事業ブランド一覧 |
| 14 | coverage_themes | 取材可能テーマ |
| 15 | assets | ロゴ・写真などの素材（Googleドライブの共有リンク） |
| 16 | usage_notes | 素材利用時の注意事項 |

### STEP 2. 受付係（Apps Script）を設置する

スプレッドシートは**社内限定の共有設定のまま**にします（「ウェブに公開」や「リンクを知っている全員」にはしない）。
代わりに、スプレッドシートに付けた小さなプログラム（受付係）が、公開してよいタブ・列だけをサイトに渡します。

1. スプレッドシートで「拡張機能 → Apps Script」を開く
2. 最初からある `コード.gs` の中身を全部消し、`apps-script/Code.gs` の中身を貼り付けて保存
3. 右上「デプロイ → 新しいデプロイ」→ 種類「ウェブアプリ」
   - 実行ユーザー：**自分**
   - アクセスできるユーザー：**全員**
4. 「デプロイ」→ 初回はGoogleアカウントの許可を求められるので承認
5. 表示された「ウェブアプリのURL」（`…/exec` で終わる）を `config.js` の `API_URL` に貼る

- 受付係が渡すのは `apps-script/Code.gs` の `PUBLIC_TABS` に書いたタブ・列だけ。`source` 列などの社内メモや `hidden` の行は外に出ない
- 新しい列をサイトに出したいときは、`PUBLIC_TABS` に列名を足してから「デプロイ → デプロイを管理 → 編集 → バージョン：新バージョン」で更新する
- 受付係は2分間データを覚えておくため、スプレッドシートの変更がサイトに出るまで最大2分ほどかかる

### STEP 3. GitHub Pages で公開

Settings → Pages → main / root を選択 → Save

## 📋 スプレッドシートのテンプレート

### タブ1: `press_releases`（公開済みのみ）

| date | title | url |
|------|-------|-----|

- **date**: PR TIMES等で**配信された日**（`YYYY-MM-DD`）
- **未配信のものは絶対に入れない**

### タブ2: `media_coverage`（公開済みのみ）

| date | title | brand | url1 | label1 | url2 | label2 |
|------|-------|-------|------|--------|------|--------|

- **date**: 記事や番組が**公開・放送された日**
- **取材を受けただけで未公開のものは入れない**

### タブ3: `speaking`（開催済み or 公式告知済み）

| date | event | venue | session | theme | attendees | satisfaction | event_url | video_url | report_url |
|------|-------|-------|---------|-------|-----------|--------------|-----------|-----------|------------|

- 開催前のものは、**主催側が公式に告知済み**の場合のみ掲載可

### タブ4: `awards`（正式発表済み）

| date | title | detail | url | crown |
|------|-------|--------|-----|-------|

- 公式発表前の受賞情報は入れない
- 殿堂入りは `crown` に `true`

### タブ5: `vision`（未来目標・ビジョン専用）🆕

| target_year | name | detail | url | url_label |
|-------------|------|--------|-----|-----------|
| 2036 | BLUEPRINT 2036（10年ビジョン） | 2026年1月発表。2036年までに売上150億円... | | |

- **このタブには未来目標・将来計画のみ**を入れる
- 実績は他タブへ（混在禁止）

### タブ6: `topics`（PRトピック・事業説明）

| topic | detail | url | url_label |
|-------|--------|-----|-----------|

- 進行中の事業説明、ブランド紹介などに使用
- **未来計画は `vision` タブへ**

### タブ7: `meta`（データ最終更新日）🆕

縦持ち形式：

| key | value |
|-----|-------|
| last_updated | 2026-04-14 |

- **ルール：アーカイブを更新したら必ず `last_updated` も更新する**

### タブ8: `variables`（変数）

| key | value | source | updated_at |
|-----|-------|--------|------------|
| 売上高_最新 | 27.1億円 | 出典 | 2026-09-27 |

- 他のタブの本文に `{{売上高_最新}}` と書くと、ここの value に置き換わって表示される
- 数字が変わったら**ここだけ**直せば、会社概要・代表プロフィール・取材テーマがすべて更新される
- `{{ }}` の中の名前は key と完全一致させる（未定義の変数はそのまま表示される）

### タブ9: `company_profile`（会社概要）

| label | value | note | highlight | hidden |
|-------|-------|------|-----------|--------|

- 行の順番どおりに会社概要の表に並ぶ
- `highlight` が TRUE の行は、ページ上部の黒い帯（会社概要バー）にも表示される
- value の中で改行すると、表示も改行される

### タブ10: `contact`（問い合わせ先）

| label | value | type | link_label | hidden |
|-------|-------|------|------------|--------|

- `type`：`email`（メールリンク）／`tel`（電話リンク）／`url`（Webリンク、表示名は link_label）／`text`

### タブ11: `ceo_profiles`（代表プロフィール文）

| no | scene | text | featured_on_mediakit | source_label | source_url | keywords | hidden |
|----|-------|------|----------------------|--------------|------------|----------|--------|

- `no` の小さい順に紹介文集に並ぶ
- `scene`（メディア／セミナー／正本 など）は紹介文集の絞り込みボタンに自動で追加される
- 文字数（短文・中文・長文）は自動判定
- `text` 内の `**太字**` は太字で表示。`{{変数名}}` も使える
- `featured_on_mediakit` を TRUE にした1行が、メディアキットの代表プロフィール欄に載る

### タブ12: `ceo_links`（関連リンク）

| title | description | url | hidden |
|-------|-------------|-----|--------|

### タブ13: `brands`（事業ブランド）

| name | category | description | url | url_label | hidden |
|------|----------|-------------|-----|-----------|--------|

- 表記は「PGHOUSE」で統一。物件王国は「不動産事業」として扱う

### タブ14: `coverage_themes`（取材可能テーマ）

| theme | detail | url | url_label | hidden |
|-------|--------|-----|-----------|--------|

### タブ15: `assets`（ロゴ・写真素材）

| name | type | url | format | usage_note | background | hidden |
|------|------|-----|--------|------------|------------|--------|

1. Googleドライブの素材フォルダを「リンクを知っている全員：閲覧者」で共有しておく
2. ファイルをアップロードし、「共有 → リンクをコピー」したURLを `url` にそのまま貼る
3. サイト側で画像プレビューとダウンロードボタンが自動で作られる

- `type`：`logo`／`photo`／`document`。`photo` の最初の1件がメディアキットの代表写真になる
- `background` に `dark` と書くと、プレビューの背景が黒になる（白抜きロゴ用）
- Googleドライブは画像配信専用サービスではないため、アクセスが極端に多いと表示が遅くなることがある

## 🛠 ファイル構成

```
.
├── index.html                        ← PR実績アーカイブ
├── mediakit.html                     ← メディアキット
├── shacho_introduction_archive.html  ← 代表 紹介文集
├── app.js                            ← 3ページ共通の動的レンダリング処理
├── config.js                         ← 受付係（Apps Script）のURL
├── apps-script/Code.gs               ← 受付係のプログラム（スプレッドシートに貼る）
├── fallback-data.js                  ← スプレッドシートを読めないときの予備データ
└── README.md                         ← このファイル
```

## ❓ トラブルシュート

- **スプレッドシートを更新したのに古い内容のまま**  
  → サイトがシートを読めず `fallback-data.js` で表示している可能性が高い。ブラウザの開発者ツール（F12）→ Console に
  「受付係 データ取得失敗」と出ていたら、`config.js` の `API_URL` と STEP 2 のデプロイ設定（アクセスできるユーザー：全員）を確認

- **「データの表示に失敗しました」**  
  → そのタブの1行目（列名）がテンプレートと一致しているか確認

- **画像が表示されない（ファイル種別の枠だけ出る）**  
  → Googleドライブのファイル（またはフォルダ）が「リンクを知っている全員」に共有されているか確認

- **新しい行を追加したのに反映されない**  
  → スーパーリロード（Ctrl+Shift+R / Cmd+Shift+R）

- **「データ最終更新日」が変わらない**  
  → `meta` タブの `last_updated` 行を更新したか確認
